# مرزهای ماژول‌ها

| ماژول | مسئولیت | وضعیت |
|---|---|---|
| identity | مجوزها، نقش‌ها و احراز هویت | OTP، رمز/TOTP کارکنان، نشست و guard سرور پیاده شده |
| catalog | دسته، تگ، برند، ویژگی، محصول و انتشار | مدیریت کامل UI/API، انتشار و ویترین عمومی پیاده شده |
| inventory | گردش، رزرو، مصرف و آزادسازی موجودی | اصلاح دستی با مجوز، version، گردش و idempotency؛ رزرو، مصرف و آزادسازی در module مشترک reservations با قفل مرتب، کنترل وضعیت و گردش فروش پیاده شده |
| checkout | اعتبارسنجی خرید، قیمت و idempotency | محاسبه سرور، ثبت سفارش، replay همان تلاش و بازیابی مالک‌محور پیاده شده |
| orders | وضعیت، تاریخچه و کنترل کارکنان | کنترل نسخه، یادداشت، آماده‌سازی، لغو پرداخت‌نشده و ارسال کامل پیاده شده |
| payments | تلاش پرداخت، verify و بازپرداخت | adapter زرین‌پال، verify و reconciliation پیاده شده؛ فعال‌سازی و بازپرداخت عملیاتی جدا هستند |
| cart | سبد مهمان/کاربر و ادغام | سبد مرورگر پیاده شده؛ ادغام بین دستگاه‌ها پیاده نشده |
| shipping | بسته و رهگیری | ثبت ارسال کامل و تحویل پیاده شده؛ اتصال حامل و ارسال جزئی پیاده نشده |
| returns | مرجوعی و موجودی قابل بازگشت | schema؛ ماژول اجرایی در مرحله بعد |
| promotions | تخفیف و سهمیه مصرف | schema؛ ماژول اجرایی در مرحله بعد |
| notifications | اعلان و سابقه ارسال | Outbox مشترک؛ provider/handler در مرحله بعد |

ماژول‌ها منطق یکدیگر را از طریق سرویس فراخوانی می‌کنند؛ برای حفظ اتمی‌بودن checkout، یک TransactionClient میان عملیات لازم مشترک خواهد بود. وابستگی به adapterهای پیامک/پرداخت در infrastructure قرار می‌گیرد.
